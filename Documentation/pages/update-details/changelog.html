Change Log

This page documents every release of WaDesk — new features, improvements, security patches, and bug fixes. Always review this page before updating so you know what has changed and whether a release introduces anything that needs attention. New entries are added to the top, so the most recent version is always first.

Before you update: Read the Update Process guide and take a full backup of your database and files. Updates ship with pre-built assets, so a standard update is upload → migrate → clear cache → restart the Node bridge.

Version 1.7.0 (September 2, 2026) — Email Inbox, LINE, WeChat & Viber

A channel release. WaDesk 1.7 adds four new channels to the unified inbox: Email (through a connected MailTrixy install), plus LINE, WeChat and Viber. Each one threads into the same Team Inbox, replies on its own transport, and reuses the auto-reply, flows, AI agent and campaign tooling you already use for WhatsApp. Run the new migrations — the build is bundled — then restart the Node bridge. Every channel is opt-in and plan-gated, so nothing changes for existing workspaces until you enable it.

Email in the Team Inbox

Your mailboxes now sit next to your chats, so a customer who emails and a customer who messages land in the same queue, worked by the same team. Email is delivered by a connected MailTrixy installation: WaDesk is the operator interface, MailTrixy remains the email engine, and WaDesk never stores a mailbox password or speaks IMAP/SMTP itself.

  • Mail in the unified inbox — email threads appear beside WhatsApp, Instagram and the rest, with assignment, notes and tags working exactly as they do everywhere else.
  • Reply from the inbox — MailTrixy performs the real send and keeps threading headers correct, so the customer sees a normal reply in their mail client.
  • History imports on link — linking a mailbox pulls its existing mail in, so you start with a populated inbox instead of an empty one.
  • Sync on demand — a per-mailbox Sync action fetches anything new and repairs anything a live delivery missed. Safe to run repeatedly; already-imported mail is skipped, never duplicated.
  • Mailboxes in the device table — each linked mailbox shows as its own row with address, provider and status, alongside your WhatsApp numbers.
  • Email flows — build automations on email with message, media, buttons, ask, delay, condition, webhook and AI steps. Quoted reply text is stripped before matching, so automation reacts to what the person wrote, not the thread quoted beneath it.
  • Email campaigns — pick Email in the campaign builder, write a subject line and body, and inherit send-now, scheduling, recurring sends, pause and resume.
  • Tenant-safe linking — a user only sees the mailboxes belonging to them, matched on their login email, so one customer can never enumerate another’s mailboxes.

Full setup, including the matching-email rule that decides which mailboxes a user can link: Email (MailTrixy).

LINE

  • Official Account messaging — connect with a Channel access token and Channel secret; no app review, usually under ten minutes.
  • Rich menus — design the tappable panel pinned to the bottom of the chat and point each area at a message, URL or flow.
  • Flex messages, quick replies, stickers and media render natively.
  • Narrowcast broadcasts — reach every friend of the account, with audience filtering and pacing that respects LINE’s rate and quota limits.
  • Token rotation — rotating channel access tokens are refreshed automatically before expiry, so the channel never goes dark.

See LINE.

WeChat

  • Official Account messaging — connect a Verified Service Account with AppID, AppSecret, Token and EncodingAESKey, including safe-mode encrypted delivery.
  • 48-hour service window — the remaining window is shown on the thread so agents know when a free-form reply will still land.
  • Template messages for contacting followers outside that window.
  • Custom menu — build the bar at the bottom of the chat and publish it to followers.
  • Mass sends to all followers or a tag-filtered subset, plus per-channel insights.

See WeChat — note that two-way chat requires a Verified Service Account.

Viber

  • One-value connect — paste the bot’s authentication token and WaDesk registers the webhook with Viber for you. Nothing to copy back.
  • Keyboards and carousels render natively from your flows and templates.
  • Read receipts — delivery and seen status show in the inbox.
  • Subscriber-aware sending — users who never subscribed are blocked with a clear reason rather than failing silently.
  • Broadcasts to every subscriber, batched at Viber’s 300-recipient limit and paced automatically.

See Viber.

  • Channel rows stay visible — connected accounts no longer disappear from the device table moments after the page loads.
  • Sidebar & navigation — missing pages restored, duplicate integration entries removed, Sales & CRM collapsed into one group, and plan-locked features now show with an upgrade prompt instead of being hidden.

Auto Reply — New Trigger Methods

Auto Reply is no longer just keyword rules. 1.5 turns it into a full Auto Responder with several ways to fire, so you can greet, deflect and cover off-hours without a flow.

  • Welcome message — automatically reply to the first message of a brand-new conversation, with no keyword required.
  • Away mode — a one-switch “we’re away” auto-reply you can flip on when the team steps out.
  • Out-of-hours replies — define working hours (days, time range, timezone) and send a different message outside them.
  • “Any message” catch-all — a default reply that fires whenever no keyword rule matches, so every inbound gets an answer.
  • Match methods per rule — Fuzzy (typo-tolerant), Exact, Contains, and Regex, plus a similarity threshold for fuzzy matching.
  • Multi-sender rules — apply one rule across several connected numbers at once, each on its own engine.
  • Priority, resend cooldown, agent hand-off pause, and excluded numbers / groups — fine control over when a rule fires and when it stays quiet.

WhatsApp Campaigns — Reach More, Faster

  • Higher throughput — an engine-aware, parallel send path lets a campaign push to many more recipients per minute while still respecting per-number pacing, so large blasts finish sooner without tripping rate limits.
  • More reliable delivery — durable retries, paused-campaign auto-restart, and stuck-midway resume mean a big send completes even after a hiccup or restart.
  • Named-parameter templates now personalize correctly — templates that use named placeholders (for example {{name}}) now fill each recipient’s real value in a campaign instead of shipping the raw {{name}} text.

  • Device connect / disconnect alerts — the in-app and email notifications for a number going online or offline now actually send when the event happens.

Personalization that scales, sharper analytics, better Meta Ads — and the bugs you asked us to fix. WaDesk 1.4 lets a single send fill a template’s variables its own way through the new per-send template variable overrides — without editing the template and changing every other campaign that uses it — rebuilds Campaign Analytics for clearer funnels and more accurate delivery reporting, tightens the Click-to-WhatsApp ad-to-chat handoff, and clears several long-standing bugs. Run the new migrations and restart the Node bridge; nothing changes for existing workspaces until you turn a feature on.

Template Variable Overrides — Per-Send Personalization

A WhatsApp template decides which contact attribute fills each {{1}}, {{2}} slot through its variable map — but that map belongs to the template. Changing what one campaign put in {{1}} meant editing the template, which silently changed every other send using it. 1.4 adds a per-send override so a single broadcast, campaign or chat send can fill the slots its own way, leaving the template untouched.

  • Override any slot, per send — set {{1}} for this broadcast only. Available in broadcasts, campaigns, the chat composer and the browser extension.
  • Blank slots fall through — leave a slot empty and it uses the template’s own variable map exactly as before. A send with no overrides behaves byte-for-byte as it did in 1.3, so nothing you already scheduled changes.
  • Literal text, tokens, or both — a slot can hold a fixed value (SAVE20), an attribute token ({{first_name}}), or a mix (Hi {{first_name}}, your code is SAVE20).
  • Tokens resolve in order — the contact row (name, phone, email, company), then the contact’s custom attributes, then your workspace attributes, then system tokens such as {{today}} and {{company_name}}.
  • Missing data never leaks braces — an unresolvable token renders empty rather than shipping a literal {{first_name}} to the customer, and the template’s own example value back-fills the blank so Meta never rejects the send for an empty parameter (error 131008).
  • Per-variant overrides in A/B tests — variant A and variant B each keep their own mapping. Previously a single mapping form appeared even when the two variants used different templates, so variant B was sent with variant A’s values.

Campaign Analytics — Sharper Insight

  • A rebuilt analytics view with clearer funnels and per-variant breakdowns, so an A/B test shows which variant actually performed.
  • Cleaner funnel & delta charts — easier to read at a glance and no longer cramped on wider date ranges.
  • More accurate click / read stats across all three engines — delivery and click reporting now reconcile with what the provider actually reported.

  • Yearly billing — a plan configured with a yearly billing period is now charged its full yearly price in a single payment, and is recognised as yearly even when the pricing-page toggle is not carried in the URL. Previously such a plan could be billed the monthly amount, or (with the yearly toggle applied to an already-yearly price) multiplied a second time. The pricing page, checkout and mobile app now all show and charge the same figure.
  • Plus many smaller fixes across the dashboard, admin panel and Node bridge.

Version 1.1.0 (June 19, 2026) — CRM, Developer Platform & In-App Updates

A major feature release that turns WaDesk from a messaging tool into a full WhatsApp business platform: a built-in sales CRM, simultaneous multi-engine sending, WhatsApp Coexistence onboarding, a public REST API with webhooks, Slack & Trello integrations, add-on packages, and — from this release onwards — a one-click in-app updater. No data migration is required beyond running the new migrations; existing workspaces keep working exactly as before.

Sales Pipeline (Deals CRM)

  • New /deals Kanban board — drag deals across your own pipeline stages, with a slide-over detail panel, activity timeline, notes, tasks, and Won/Lost outcomes.
  • Connected everywhere: a deal can be created manually, from the Team Inbox ("Create deal" on any chat), automatically from a store order (opt-in), from a flow node, or over the REST API. Each deal links to its contact and conversation.
  • Flow bridge (both directions): moving a deal to a stage fires the deal_stage_changed trigger to launch a WhatsApp flow; and a flow can itself create or advance a deal.
  • Reports at /deals/reports (value by stage, win-rate, forecast, agent leaderboard) and overdue-task reminders that nudge the deal owner. Gated by the access_sales_pipeline plan feature.

WhatsApp Coexistence

  • Onboard a number that is already running on the WhatsApp Business app via Meta's Embedded Signup — without losing chat history or mobile access.
  • Launches Embedded Signup with Meta's whatsapp_business_app_onboarding feature and correctly skips phone registration (registering would remove the number from the Business app).
  • Mirrors the app side into your Team Inbox via Meta's coexistence webhooks: smb_message_echoes (messages sent from the app), smb_app_state_sync (the business's contacts), and history (past messages). Enabled by the admin under Settings.

Run Multiple Engines at Once

  • A workspace can now connect any combination of the Unofficial API, WhatsApp Cloud API, and Twilio at the same time, not just one engine.
  • Device pickers, campaigns, broadcasts, scheduled sends, flows, and the inbox all show grouped, per-engine senders; the right engine is resolved per message, and replies go back out on the channel a customer used.

Developer Platform — REST API & Webhooks

  • Customer REST API at /api/v1 — 50+ endpoints for messages, broadcasts, campaigns, scheduled sends, contacts & groups, deals, flows, templates, devices, and account info. Authenticated with per-workspace API keys (Bearer or X-Api-Key), minted under More → Developers. Every send routes through the same battle-tested controllers the dashboard uses.
  • Live API reference (OpenAPI) at /developers/docs, generated from the code so it always matches the real endpoints.
  • Outgoing webhooks — subscribe a URL to 17 events (message received/sent/delivered/read/failed, broadcast & campaign status, contact & device events) delivered as a signed JSON POST (X-WaDesk-Signature, HMAC-SHA256). Managed under Webhooks.
  • Incoming webhooks — generate an inbound capture URL that records every request (and can relay it onward), under Webhooks → Incoming.

New Integrations — Slack & Trello

  • Slack: send a WhatsApp message straight from Slack with a signature-verified slash command (/wa send name: message).
  • Trello: board webhook support — e.g. assigning a member to a card can trigger a WhatsApp action.

Add-on Packages

  • Sell à-la-carte feature packs on top of a plan (like credit packages, but for features/limits). Add-ons are bought after a plan and shown on a dedicated Add-ons tab in the customer's account.
  • Managed in a separate admin CRUD under Admin → Add-ons; an add-on's flags and limits stack on top of the base plan.
  • New optional data-retention control: a plan/add-on can auto-wipe a workspace's data a set number of days after the plan expires.

Reliability & Messaging Improvements

  • Durable send auto-retry across campaigns, scheduled messages, and broadcasts — if a device is offline when a send fires, the unsent recipients are automatically retried on reconnect with backoff, paced (never a bulk blast) and never re-sending anyone who already received it.
  • Connection stability — Unofficial API numbers reconnect on their own and stay connected until you log out, with a QR-refresh watchdog.
  • Campaign A/B testing, faster auto-replies (no forced cool-down), and reliable media in flows and auto-replies.

In-App Updater (new)

  • From this release, the Admin panel includes a one-click updater under Admin → Update: verify your CodeCanyon purchase → automatic backup → upload the update ZIP → apply files → run migrations → finalize (clear caches + health check), with one-click rollback to any backup.
  • It preserves your .env, storage/, and uploads automatically — so future updates no longer require manual file replacement over FTP/SSH. See the Update Process guide.
Upgrading from 1.0.0? 1.0.0 has no in-app updater, so the move to 1.1.0 is a manual file replacement (back up → replace app code, keep .env + storage/ + uploads → php artisan migrate --force → clear caches → restart the Node bridge). From 1.1.0 onward you can update from inside the admin panel. Full steps: Update Process.

Version 1.0.0 (May 29, 2026) — Initial Release

The first public release of WaDesk, a self-hosted, multi-tenant WhatsApp business platform built with Laravel 12, Tailwind CSS, Alpine.js, and a bundled Node.js bridge. WaDesk ships as a complete SaaS product — team inbox, bulk campaigns, automation, an AI suite, and a full admin panel with plans and billing.

WhatsApp Engines

  • Unofficial API: Connect any WhatsApp number by scanning a QR code, powered by the bundled Node.js bridge. No Meta approval required.
  • WhatsApp Cloud API (Meta): Official Graph API v23 integration with template management and WhatsApp Forms (Meta Flows).
  • Twilio WhatsApp: Send through a Twilio WhatsApp sender using Content Templates (ContentSid).
  • Engine-agnostic core — the inbox, campaigns, flows, and templates all adapt to whichever engine a workspace is connected to.

Team Inbox & Messaging

  • Shared Team Inbox with conversation assignment, internal notes, labels, and SLA tracking.
  • Team Chat for internal agent-to-agent messaging.
  • Bulk campaigns and broadcasts with audience targeting, pacing/throttle controls, and per-recipient delivery status.
  • Scheduled sends and a full message history with delivery and read receipts.
  • Auto-reply rules for instant responses to inbound messages.

Templates & Automation

  • WhatsApp template management with linting to reduce rejection and ban risk.
  • Visual flow builder for drip and trigger automations.
  • WhatsApp Forms (native Meta Flows on the Cloud API engine).
  • Chatbot widget for embedding a Click-to-WhatsApp entry point on any website.
  • WhatsApp Links (wa.me-style short links) with click tracking and redirects.

AI Suite

  • AI chatbots trained on your own content, with pluggable provider keys (OpenAI, Anthropic Claude, Google Gemini).
  • AI Call Assistant — an AI voice assistant that answers phone calls, with full call logs.
  • Per-workspace AI training sources and configuration.

Marketing, Contacts & Growth

  • Contacts management with custom attributes and segmentation.
  • Click-to-WhatsApp ads via Meta (Meta Ads integration).
  • Analytics dashboards powered by ApexCharts.
  • Appointment booking with Google Calendar / Meet links.

Integrations

  • Shopify and WooCommerce store connections for order updates and cart recovery.
  • HubSpot CRM sync.
  • Google Sheets add-on and outbound webhooks.
  • WhatsApp product catalog and storefront support.

Admin Panel & SaaS

  • Full multi-tenant admin panel with isolated workspaces and role-based team access.
  • Subscription plans with granular per-plan feature gating, free trials, coupons, and wallet credits.
  • 30 payment gateways with multi-currency support and live exchange rates.
  • White-label branding (logo, colors, app name, message footers) per platform and per workspace.
  • Admin support inbox with SLA policies, announcements, guidebook, order and billing history, and financial reporting.
  • Impersonation, user management, language management, and translation providers.

Security

  • Two-factor authentication (2FA) and role-based permissions.
  • Audit log of every sensitive admin action.
  • IP / location controls and rate limiting.

Installation & Infrastructure

  • Web installer wizard — upload files, create a database, visit your domain; migrations, default data, and the admin account are handled automatically.
  • Bundled Node.js bridge for QR pairing, sending, and inbound webhooks.
  • Database queue driver by default (configurable to Redis).
  • Multi-language support and a clean, responsive UI built with Tailwind CSS and Alpine.js (compiled with Vite).
